## 项目名称

FrameTrail 帧迹：基于 MoonBit 的设备数据流分帧与故障诊断库

## 一句话介绍

用 MoonBit 将碎片化设备字节流还原成经过校验的数据帧，提供有界缓存、错误定位和可复现的离线回放，帮助开发者处理半包、粘包与损坏输入。

## 项目简介 可复制到报名表

FrameTrail 帧迹是面向设备数据接入和通信调试场景的 MoonBit 开源基础组件。串口、蓝牙或网络接收端获得的是连续字节流，一次读取不一定对应一条完整消息；实际开发需要处理半包、粘包、错误校验码和异常长度，并在出现问题后恢复处理。项目将这些通用需求收敛为独立于传输层的增量分帧库，并提供命令行回放工具，使问题可以用一份十六进制日志复现。

首版采用明确的参考帧格式 COBS(payload + CRC16) 加零分隔符，实现 COBS 编解码、CRC-16/IBM-3740 校验、任意块增量输入、最大待解析长度限制、五类结构化错误与绝对字节区间报告。开发者可以将核心库嵌入 MoonBit 应用，也可以用 CLI 编码载荷、解码输入或回放日志。COBS 与 CRC 为已有算法，项目贡献在于 MoonBit 实现、可解释的错误恢复机制、边界约束和完整复现链路。

当前本地首版已在 JavaScript 与 WebAssembly GC 目标上分别通过 25 项测试；另有独立 Python 参考检查交叉验证 15 组双向帧向量及真实 CLI 进程行为。测试包含 1024 组确定性编解码生成样例、损坏流切块一致性与恢复检查。项目使用 Apache-2.0 许可证，核心编解码、状态机和报告逻辑均由 MoonBit 实现。后续将补齐公开仓库、远程 CI 与本人复现记录，并根据实际设备需求增加传输适配器。尚未完成真实硬件联调，不将计划写为已有成果。

## 工程目标与首版范围

| 目标 | 当前交付证据 | 验证方式 |
|---|---|---|
| 任意切块输入仍恢复完整帧 | Decoder.feed 增量 API | 所有切分点及 1 至 64 字节块检查 |
| 损坏输入可诊断并继续处理 | 五类错误及恢复状态机 | 坏帧位于两条正常帧之间的演示 |
| 异常流不会无限堆积待解析字节 | max_encoded 限制 | 100000 字节无分隔符输入检查 |
| 结果能被第三方复现 | README、示例、测试与参考脚本 | JS 与 wasm-gc 各 25 项测试通过 |
| 可被其他项目复用 | 纯核心库与最小 CLI I/O 适配 | MoonBit 公共接口与开源许可证 |

不包含：真实串口/蓝牙驱动、图形界面、任意协议自动识别、重传机制、载荷业务字段解析和生产环境性能承诺。

## 技术路线

输入字节块 → 有界分隔符状态机 → COBS 解码 → CRC16 校验 → 帧或错误事件 → JSON 回放报告。

核心库不依赖操作系统设备接口；CLI 仅用少量 JavaScript FFI 读取文件及设置退出码。超限输入在首次越界时报告一次，随后丢弃至下一个零分隔符。每个事件保留绝对字节位置，因此可以把现场日志中的问题对应到具体数据区间。流终结时显式检查未完成帧。

时间复杂度为 O(N)，待解析逻辑缓存为 O(L)，L 为用户指定的上限。输出事件、数组容量和 CLI 保存的完整输入不属于该逻辑缓存界限。错误恢复依赖下一个分隔符，不能保证恢复所有受损帧。

## 差异化与生态价值

重点是面向通信故障的工程可用性：同一输入不论如何切块均给出一致事件；异常长度有明确资源边界；错误结果携带可定位的字节区间；离线日志和独立参考检查可以成为其他 MoonBit 设备项目的回归测试材料。

前期公开检索发现，MoonBit 生态已经存在 JSON Schema 校验、CSV 数据质量和任务图组件，因此本项目选择更聚焦的设备流故障回放场景。有限检索不能证明独创性；申报不使用“国内首个”“填补空白”或未经验证的性能领先表述。COBS 和 CRC 的算法来源在 README 中说明，未复制第三方实现代码。
